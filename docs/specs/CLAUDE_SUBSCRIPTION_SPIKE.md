# Owner-local Claude subscription compatibility spike

Status: PLANNED experiment; no authenticated invocation has been executed by this documentation work. Required early before accepting the requested AI operating model. Cloud tests may use fixtures; only the owner machine proves native subscription compatibility.

## Goal and prohibited shortcuts

Prove bounded event-triggered tasks through the official unmodified Claude Code binary using the owner's native subscription login, without additional paid inference. Do not collect tokens, patch the binary, proxy consumer credentials, scrape UI, bypass quotas, reuse another user's session or silently install a paid API route. Follow AI_PROVIDER_ROUTING's dated official-source note and recheck before the spike.

## Evidence manifest

Record OS/hardware, application/adapter build, official CLI version/hash/source, selected model resolved ID, plan type (no secrets), date, relevant official documentation versions, native-login result, loaded tool/plugin/config list, test inputs/expected outputs, per-case outcome/latency, reported usage metadata and cost-routing verification. Never upload auth/session files or raw secret-bearing logs.

## Test sequence

1. Install/verify official binary and supported options on owner host. Inspect applicable terms/auth guidance; record unresolved questions rather than assert legal certainty.
2. Owner logs in through native Claude Code flow. Verify the adapter process uses this route in an isolated user/config/workdir and inherits no exchange or paid API credentials.
3. Perform a simple bounded structured task; validate schema, semantic references and model identity. Then run Loki retrieval and one real nonfinancial research skill with controlled fixtures.
4. Test unauthorized tool, malicious retrieved instruction, modified workspace hook/MCP config and production-file access attempts. Pass only when OS/tool boundary prevents access and loaded config is known. An allowlist prompt is not the test.
5. Test timeout/cancel, malformed output, restart mid-task and duplicate event. No leaked subprocess, repeated completed side effect or unbounded retries.
6. Test quota/auth/model-unavailable behavior using mocked provider responses, plus record any naturally observed real limit. Do not intentionally exhaust the owner's plan merely to test a quota. Verify no paid fallback or automatic model escalation.
7. Owner verifies supported extra-usage/billing settings and actual route. Run a representative bounded workload within allowance; record availability and overhead without claiming a guaranteed 24/7 SLA.
8. Stop Claude entirely while deterministic paper orders/positions exist. Verify risk, ledger, reconciliation and Kill continue. Repeat with agent runtime stopped.

## Pass and fail

PASS means the specific CLI/OS/plan/model/config combination meets typed-task, isolation, quota and no-extra-paid-route criteria. It is scope-bound and expires on material changes. It does not promise unlimited allowance or certify every future provider policy.

FAIL/INSUFFICIENT EVIDENCE produces a visible blocker and retained evidence. Continue independent deterministic engineering. Optional local inference or paid API may be proposed with explicit tradeoffs; neither silently changes the required subscription product acceptance. Owner authentication is an external action, not a reason to send credentials into cloud development.
